# TPCMS API Documentation

`openapi.yaml` (source of truth) and `swagger.json` (generated from it) in this directory
describe every existing backend endpoint, generated by reading the actual route/controller/
validation source in `src/modules/**` — not by copying `api_documentation.md`, which was found
to be stale/incorrect in several places (see `x-known-discrepancies-with-legacy-doc` at the top
of `openapi.yaml` for the full list, e.g. wrong approval_id values, wrong status_id defaults,
wrong query-vs-body placement for the training-application status update, a fabricated
self-service change-password endpoint that doesn't exist).

**No backend code, route, or behavior was changed to produce these files.**

## Viewing the docs

Either file can be pasted into the [Swagger Editor](https://editor.swagger.io) for an
interactive read, or served locally without touching any backend source:

```bash
npx -y http-server . -p 8080   # from backend/, then open http://localhost:8080/swagger.json
                                 # in editor.swagger.io's "Import URL"
```

## Optional: mounting Swagger UI in the running server

Not applied (would be a backend code change), but if the team wants a `/api-docs` route later,
it's a two-step addition:

```bash
npm install swagger-ui-express
```

```ts
// in app.ts, alongside the other app.use(...) route mounts
import swaggerUi from "swagger-ui-express";
import openapiDocument from "../swagger.json" with { type: "json" };

app.use("/api-docs", swaggerUi.serve, swaggerUi.setup(openapiDocument));
```

## Keeping this current

`openapi.yaml` is hand-authored against the source as of this refactor. If routes/validation
change afterward, regenerate `swagger.json` from the updated YAML rather than editing both by
hand:

```bash
node -e "const y=require('js-yaml'),fs=require('fs');fs.writeFileSync('swagger.json',JSON.stringify(y.load(fs.readFileSync('openapi.yaml','utf8')),null,2))"
```

(requires `js-yaml` — `npm install --save-dev js-yaml` if not already present)
